# SmokeHere MVP PRD

- 작성일: 2026-08-08
- 상태: Draft

## 1. 배경 및 문제 정의

흡연자는 낯선 지역에서 흡연구역을 찾는 데 불필요한 시간을 쓴다. 이 서비스를 구상하게 된 두 가지 구체적 경험이 있다:

- 용산에 영화를 보러 갔을 때 흡연구역이 어디인지 몰라 직접 찾아봐야 했다.
- 회사가 다른 지역으로 이전하면서 새 지역의 흡연구역을 다시 찾아야 했다.

또한 일본에는 지역별로 QR 코드를 통해 접근하는 흡연구역 웹앱이 이미 존재한다. 한국에는 이런 서비스가 없다는 점에서 출발했다.

**설계 철학**: 처음부터 기술을 많이 넣는 것이 좋은 설계는 아니다. 이 프로젝트의 기술적 재미는 라이브러리 개수가 아니라 다음 흐름에 있다.

> 공공데이터 정규화 → 위치 기반 탐색 → 지역 단위 캐싱 → 로그인 없는 LocalStorage 개인화 → SEO/QR 접근 → 외부 지도에 길찾기 책임 위임

## 2. 목표 및 성공지표

**목표**: 회원가입 없이, 낯선 지역에서도 몇 초 안에 가장 가까운 흡연구역을 찾고 길찾기까지 연결할 수 있게 한다.

**성공지표 방향**: 지속 사용 지표(재방문율, 북마크 저장 사용자 비율)를 핵심으로 본다.

> **확인 필요**: 구체적인 목표 수치(예: 런칭 후 N개월 내 재방문율 X%, 북마크 저장 사용자 비율 Y%)는 아직 정해지지 않았다. 7번 섹션에도 기재.

## 3. 사용자 시나리오 / 유저 플로우

**시나리오 A — 낯선 지역에서 급하게 찾는 경우**
용산에서 영화를 보고 나온 사용자가 SmokeHere에 접속한다. 로그인 없이 바로 현재 위치 기반으로 주변 흡연구역이 거리순으로 지도에 표시된다. 가장 가까운 곳을 선택해 상세 정보를 확인하고, "길찾기"를 누르면 Google Maps 앱/웹이 열려 도보 경로를 바로 안내받는다.

**시나리오 B — 여행자/방문자가 임시 거점을 등록하는 경우**
해외에서 방문한 사용자가 호텔에 체크인한 뒤, 호텔 위치를 "자주 가는 장소"로 북마크한다. 이후 외출할 때마다 호텔 북마크를 기준으로 주변 흡연구역을 다시 검색한다.

**시나리오 C — QR로 진입하는 경우**
특정 건물/구역에 부착된 QR 코드를 스캔하면 해당 위치를 기준으로 흡연구역 검색 화면이 URL Search Params를 통해 바로 열린다.

## 4. 기능 요구사항

**서비스 지역**: 1차 MVP는 서울/수도권을 우선 출시 지역으로 한다 (공공데이터 커버리지가 가장 두터운 지역). 전국 확대는 이후 단계에서 검토한다.

## 5. 비기능 요구사항

- **성능**: 공공 API를 클라이언트가 직접 호출하지 않고 Next.js Route Handler를 통해 Proxy — API 키 보호 및 응답 정규화.
- **캐싱 정책**: 공공데이터는 24시간 주기로 갱신되므로 Next.js Data Cache로 24시간 캐싱. 자주 사용되는 검색어도 캐싱해 반복 조회 비용을 줄인다.
- **데이터 정합성**: 서로 다른 지자체 공공데이터 포맷을 TypeScript로 정의한 공통 `SmokingArea` 모델로 정규화해 프론트엔드가 단일 형태로 소비한다.
- **개인정보/보안**: 로그인·회원가입이 없어 개인 식별 정보를 서버에 저장하지 않는다. 북마크·최근 검색어는 사용자 브라우저의 LocalStorage에만 저장되며 서버로 전송되지 않는다.
- **DB 의존성 없음(MVP)**: 1차 MVP는 데이터베이스 없이 동작한다. 사용자 제보(2차) 도입 시에만 Supabase PostgreSQL을 추가한다.

## 6. 범위 제외 (Out of Scope)

MVP의 개발 범위를 "흡연구역 찾기"에 집중시키기 위해, 길찾기는 Google Maps Deep Link로 전적으로 위임하고 아래 항목은 만들지 않는다:

- Google Routes API 연동
- 경로 계산용 서버 API 구현
- 출발지 → 목적지 경로 계산
- Polyline 경로 렌더링
- 예상 도보시간 계산 API
- 경로 관련 에러 처리
- 경로 데이터 캐싱
- 길찾기 관련 상태관리

그 외 MVP에서 제외하는 것:

- 로그인/회원가입 (전체 서비스에서 의도적으로 배제)
- 데이터베이스 (Supabase는 2차부터 도입)
- 사용자 제보/신고 기능 (2차)
- 지도 위 음식점·헬스장·클라이밍장·공원 등 부가 정보 (3차)
- 네이티브 앱/Capacitor (4차)
