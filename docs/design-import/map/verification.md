## 브라우저 확인

### 키보드 순회

포커스 순서를 실측했습니다.

```
0:a[SmokeHere…] → 1:a[소개] → 2:a[지도] → 3:a[지도 열기]
→ 4:input[검색] → 5~9:input[전체/서울/부산/인천/대구]
→ 10~12:input[형태 3종] → 13:button[내 위치에서 찾기] → 목록 항목
```

목록 항목에 포커스 후 **Enter로 상세 패널이 열리고 포커스가 패널로 이동**하는
것을 확인했습니다.

## 육안 확인에서 발견해 고친 것

자동 검증이 전부 통과하는데 화면을 보고서야 드러난 문제 2건입니다.

### 1. 페이지 전체가 스크롤되고 목록 내부 스크롤이 죽어 있었음

```
viewport 911 / document 1656  → 페이지 스크롤 발생
aside 1587px (콘텐츠만큼 늘어남)
목록 scrollHeight(1339) == clientHeight(1339) → 내부 스크롤 없음
```

원인은 루트 레이아웃의 `body`가 `min-h-full`이라 **확정 높이가 없다**는 것.
`flex-1` + `min-h-0`은 부모에 확정 높이가 있어야 제약이 됩니다.
지도 페이지 컨테이너를 `h-dvh`로 바꿔 해결했습니다.

```
수정 후: viewport 911 / document 911 → 페이지 스크롤 없음
        목록 scrollHeight 1339 > clientHeight 594 → 내부 스크롤 동작
```

### 2. 패널을 닫으면 포커스가 `<body>`로 떨어졌음

키보드 사용자가 문서 맨 위로 튕깁니다. 처음에는
`requestAnimationFrame`으로 목록 항목에 포커스를 돌려주려 했는데
**브라우저에서는 동작하지 않았습니다** — 패널이 DOM에서 제거되며 브라우저가
포커스를 `<body>`로 되돌리는 것과 경합했습니다.

`useLayoutEffect`(커밋 직후 실행)로 바꿔 해결했습니다.

```
Esc      : 닫힌 뒤 포커스 spotId "11" — 원래 항목 ✅
닫기 버튼 : 닫힌 뒤 포커스 spotId "11" — 원래 항목 ✅
```

> **⚠ 이 버그는 테스트가 잡지 못했습니다.** `requestAnimationFrame` 버전에서도
> vitest는 통과했습니다. jsdom의 타이밍이 실제 브라우저와 달라서입니다.
> 테스트는 회귀 방지용으로 유지하되, **포커스 관리는 브라우저에서 확인해야
> 한다**는 사실이 이번에 드러났습니다.

## 미해결 항목

1. **지도 연동 미실행.** 의도된 보류입니다. 보류 범위는
   [map-placeholder.md](map-placeholder.md)의 표를 그대로 체크리스트로 쓰세요.
2. **"내 위치에서 찾기"를 실제로 눌러 보지 않았습니다.** 권한 프롬프트가
   브라우저 자동화를 막을 수 있어 건너뛰었습니다. 권한 거부·미지원 분기는
   코드로만 확인했습니다.
3. **형태 칩 미선택 상태의 테두리 대비를 재검토하지 않았습니다.**
   `border-hairline`(1.36:1)인데, 체크 아이콘과 라벨이 컨트롤임을 알리므로
   테두리가 유일한 식별 수단은 아니라고 판단했습니다.
4. **흡연구역 데이터는 시안의 샘플입니다.** 좌표·운영시간·수용 인원·갱신일이
   검증되지 않았습니다 (`lib/map/spots.ts` 상단 주석).
5. **`docs/design-guide.md`가 여전히 갱신되지 않았습니다.** Home 작업에서
   추가한 토큰들이 아직 반영돼 있지 않습니다.
