# 지도 영역 자리표시자

> 상태: **완료** · 태스크 #13 · 2026-08-09

## 범위

실제 지도 대신 회색 자리표시자를 렌더합니다. **지도 연동은 퍼블리싱과 기능이
연결된 뒤 마지막 단계에서 진행합니다.**

## 원본

`Map.dc.html` → `<main>` 블록, 스크립트의 `initLeaflet` / `loadGoogle` /
`syncMarkers` / `_syncLeaflet`

## 구현 대상

`components/map/map-canvas.tsx`

## 이번 범위에서 제외한 것

**삭제가 아니라 보류입니다.** 시안에는 있지만 지금 구현하지 않습니다.

| 제외 항목 | 시안의 위치 |
|---|---|
| Google Maps JavaScript API 로드 | `loadGoogle(key)` — `maps.googleapis.com` 스크립트 주입 |
| API 키 입력 모달 | `sc-if value="{{ keyPanel }}"` 블록 |
| API 키 localStorage 저장 | `localStorage.setItem("smokemap.gmapsKey", k)` |
| 헤더의 "구글 지도로 전환" 버튼 | `<button onClick="{{ openKeyPanel }}">` |
| Leaflet + CARTO 타일 | `initLeaflet()`, `L.tileLayer(...)` |
| 마커·툴팁·`fitBounds` | `_syncLeaflet()`, `syncMarkers()` |
| `ResizeObserver` 기반 `invalidateSize` | `this._ro` |

**npm 패키지를 새로 설치하지 않았습니다.** Leaflet도 Google Maps 로더도
필요 없습니다.

### API 키를 다루지 않기로 한 것의 부수 효과

시안은 사용자가 **자기 API 키를 입력창에 붙여넣게** 합니다. 키가
localStorage에 평문으로 남고, 키 입력 UI가 있으면 사용자가 자기 키를 노출할
경로가 생깁니다. 이번 범위에서 빠지면서 그 문제도 함께 사라졌습니다.
지도를 붙일 때는 **키를 사용자에게 받지 않고 서버 환경변수로 관리**하는 쪽을
검토해야 합니다.

## 자리표시자가 지도 자리임을 남긴 방법

세 겹으로 남겼습니다.

1. **컴포넌트 상단 주석** — 왜 아직 지도가 없는지, 무엇을 뺐는지, 붙일 때
   손댈 지점 4가지
2. **`data-map-placeholder="true"` 속성** — 코드·테스트·DOM 검색에서 식별 가능
3. **화면 안내** — "지도는 준비 중입니다" + 목록으로 유도하는 문구

## 결정 기록

### 실제 지도인 척하지 않는다

`#E9E7DF`(시안의 타일 바탕색)를 그대로 깔면 **타일이 로드되지 않은 지도처럼**
보입니다. 사용자는 지도가 고장 났다고 생각합니다. `surface-strong`(#f2f2f2)
회색에 "준비 중" 안내를 얹어 **의도된 상태**임이 드러나게 했습니다.

### 안내 문구를 `aria-hidden`으로 감추지 않는다

장식이 아니라 **정보**입니다. 지도가 없다는 사실은 스크린리더 사용자도 알아야
합니다. 대신 `pointer-events-none`으로 위에 얹힐 오버레이·상세 패널의 클릭을
막지 않게 했습니다.

### 지도 없이도 기능이 성립해야 한다

흡연구역의 이름·주소·거리·운영시간·형태는 전부 좌측 목록이 전달합니다.
지도는 **보조 수단**이지 유일한 경로가 아닙니다. 이 구조는 지도를 붙인 뒤에도
유지해야 합니다 — 스크린리더 사용자와 저사양 기기에서 그대로 유효합니다.

### `children`을 받는 컨테이너

오버레이 배지(#17)와 상세 패널(#16)이 지도 위에 겹칩니다. `relative`
컨테이너로 두고 자식을 받게 했습니다.
