# ✅ 작업 완료 체크리스트

**실제로 실행하고 출력을 확인한 뒤**에 완료라고 말합니다.
실행하지 않은 항목을 통과했다고 쓰는 것은 `AGENTS.md` 강제 규칙 4
("추측을 사실처럼 말하지 않는다") 위반입니다.

## 1. 린트 — 통과할 때까지

```bash
npm run lint
```

오류가 나면 고치고 다시 실행합니다. `eslint-disable`로 경고를 지우지 마세요.
정말 필요하면 이유를 주석으로 남기고 사용자에게 보고하세요.

## 2. 타입 검사

```bash
npx tsc --noEmit
```

`any`로 회피하지 마세요. 타입이 안 맞으면 대개 설계가 어긋난 것입니다.

## 3. 테스트

```bash
npm test
```

**실패하면 먼저 물으세요 — 틀린 것이 테스트인가, 제품인가?**
테스트를 고쳐 통과시키기 전에 판단하세요. 제품이 틀렸다면 제품을 고치고
`issue-reporter`에게 기록을 위임합니다.

동작을 바꿨다면 테스트를 추가합니다(`vitest-rtl-expert`에 위임).
테스트가 없는 영역이면 "테스트 없음"이라고 솔직히 보고하세요.

## 4. 빌드

```bash
npm run build
```

프로덕션 빌드에서만 드러나는 서버/클라이언트 경계 오류가 있습니다.

## 5. 실제 화면 확인 (UI 변경 시 필수)

**테스트 통과는 화면이 멀쩡하다는 뜻이 아닙니다.** jsdom은 레이아웃을 계산하지
않아 겹침·넘침·잘못된 간격을 잡지 못합니다.

1. `claude-in-chrome` 스킬을 먼저 호출합니다 (브라우저 도구 사용 전 필수).
2. `npm run dev`를 **백그라운드로** 띄웁니다.
3. 새 탭에서 해당 경로를 엽니다. 컴포넌트 검수는 `/showcase`에서 모든 variant를
   한 번에 볼 수 있습니다.
4. 확인할 것:
   - 레이아웃이 깨지거나 요소가 겹치지 않는가
   - 콘솔에 에러·경고가 없는가 (`read_console_messages`)
   - 좁은 화면에서 가로 스크롤이 생기지 않는가
   - `Tab`으로 포커스 링이 보이는가
   - **디자인 토큰이 실제로 적용됐는가** — `cn()` 병합 문제로 클래스가 조용히
     사라진 전례가 있습니다 (`docs/issue/`)
5. 탭을 닫고 개발 서버를 정리합니다.

> `alert` / `confirm` / `prompt`를 띄우는 요소를 클릭하지 마세요.
> 브라우저 모달이 뜨면 이후 자동화 명령이 전부 멈춥니다.

화면을 못 봤으면 **"확인하지 못했다"고 명시**하세요.

## 6. 정리

- 조사용 임시 파일·스크립트 삭제
- 백그라운드 개발 서버 종료
- 발견한 이슈를 `issue-reporter`에게 기록 위임
